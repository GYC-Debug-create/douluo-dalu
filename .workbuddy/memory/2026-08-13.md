# 2026-08-13 工作日志

## 全项目只读代码审查（架构 + 性能 + 游戏体验 bug）

产出：`代码审查报告-架构与性能优化.md`（项目根目录），未修改任何代码。

### 核心发现（按严重度）
- **H1 高**：战斗中切页后 `useBattleSystem.js:152` 模块级 `battleState` 残留，`nextEvent()` 被 `isActive()` 拦截（useEventEngine.js:1198），游戏卡死只能刷新。GamePage.vue:277 卸载只清定时器不清理战斗。
- **H2 高**：`serializer.js:310 saveToLocal()` 每次全量深拷贝 + localStorage 7 份副本（backup+hist1..5），逼近 5MB quota 后"自动存档失败"。
- **H3 高**：`useEventEngine.js:828 addDiaryEntry` 无长度截断（对比 mapBridge.js:158 有 slice(-200)），存档无限膨胀，云端 2MB body 限制（server.js:24）最终必失败。
- **H4 高（部署）**：Dockerfile 缺 `COPY public ./public`，`/api/spirits` `/api/beasts` 的 `require('./public/data/*.json')` 在容器内 500。
- **M1**：GamePage.vue:257 backgroundSave 不处理 409 conflict，云存档长期不同步。
- **M2**：nextEvent 每次全量遍历 600~700+ 事件做 adaptEvent 过滤 + createGProxy 每次建新 Proxy，移动端探索卡顿。
- **M3**：/api/player/list（server.js:397）同步 readdirSync + JSON.parse 全部存档，TitlePage 进首页即触发。
- **M4**：RING_LEVELS ×3、phaseForLevel ×3 等规则常量多处重复定义。
- **M5**：engine/combat.js 988 行死代码（无 import，依赖未定义全局）。
- **M6**：主 bundle 481KB 无分包无懒加载；dist 被旧版产物污染（game.js 324KB 等 ~2MB）；无 gzip；静态缓存仅 1h。
- 低：v-for index key、CreatePage 返回动画恒 false、_currentLocation 死字段、ParticleBackground RAF 死代码等。

### 优化思路（报告第四部分）
战斗状态迁 Pinia / resetBattle；存档改 IndexedDB + 防抖合并 + diary 截断；事件按 location 预索引；后端异步 fs + list 缓存 + gzip；路由懒加载 + webp 切图；规则常量单一来源；删死代码。

### 项目事实
- 技术栈：Vue 3 + Pinia + Router 前端，Express 单文件后端，文件系统存档（data/player_*.json，现有 99 个，最大 133KB）。
- vite publicDir 指向 `../public`，构建时整个 public 复制进 dist。
- 存档 ID 形如 `p_xxx`，云端乐观锁 + v1..v5 历史版本机制。
- 部署：docker-compose（127.0.0.1:3001:3000）+ nginx 反代 gyc1313.tech。
