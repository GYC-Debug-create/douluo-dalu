> 说明：本文沉淀「入口与框架」板块的深度体验调研结论、当前开发进度与后续开发方向。
> 对应完整报告的保留在 `docs/reports/` 下（技术视角 + 玩家视角两份）。

## 一、调研范围与基线

### 1. 调研对象（板块 A 全部相关文件）
| 文件 | 角色 |
|---|---|
| `server.js` | Node 后端：静态服务 + 存档 API |
| `public/game.html` | 正式版 · 文字 RPG（主界面 + 内联约 1600 行 CSS） |
| `public/index.html` | 旧版 Canvas 原型（教学原型，非正式玩法） |
| `public/map.html` | 万象地图（独立页，内置 iframe 嵌入游戏） |
| `public/codex.html` | 万象图鉴（独立页，内置 iframe 嵌入游戏） |
| `public/css/style.css` | 旧版 Canvas 样式 |
| `public/css/text-combat.css` | 文字版战斗样式（**注意：不是主样式**） |

### 2. 实测基线
- `npm test`：44 / 44 全部通过。
- `npm run validate:data`：通过（13 个 JSON / 9 个魂环事件）。
- 起服务实测所有入口路由均返回 200：
  `/`、`/index.html`、`/game.html`、`/map.html`、`/codex.html`、`/css/text-combat.css`、`/css/style.css`、`/api/spirits`、`/api/player/list`。

### 3. 总体结论（技术审查）
入口都能打通，**没有打不开页面的 P0**。板块 A 真正的问题集中在三类：
1. **两个入口共用同一存档后端，但档案格式互不相认**（旧 Canvas 不改灵魂体，`migrateSave` 一失败就把人拉回标题页）。
2. **样式不是"两套 CSS"，而是实际有 4~5 套主题 token** 各自漂移（game.html 内联才是正式版真正的主样式，token 值在各页面各不相同）。
3. **iframe 消息完全不校验来源**：`game.html` 的 `message` 监听只查 `e.data.type`，不查 `e.origin` / `e.source`，任意页面发消息即可指使游戏切屏/导航（E-6 校验缺失部分）。

## 二、调研发现的关键问题清单（按严重度）

| 编号 | 问题 | 证据 | 状态 |
|---|---|---|---|
| A-1 | 两个入口同名同体验，玩家分不清"新旧"——text RPG / 旧 Canvas 都叫"武魂觉醒" | `index.html` 标题「斗罗大陆-武魂觉醒」，大功能在 `/game.html` | ✅ 已解决（E-1） |
| A-2 | 创建流程无时间预期、无推荐引导，不了解出身差异 | 标题 3 个按钮，"出身"超过"快进" | ✅ 已解决（E-2） |
| A-3 | 标题页「万象图鉴」直接全量剧透所有词条 | `btn-codex` 直接跳图鉴 | ✅ 已解决（E-3） |
| A-4 | 新角色开局继承旧角色残留的 Toast/成就横幅/等级通知/新手引导 | `btn-new` 只重置 newChar，不清 DOM 通知 | ✅ 已解决（E-4） |
| A-5 | 存档列表没有分组与"优先"认知 | `saveList` 本地/云端条目混排 | ✅ 已解决（E-5） |
| A-6 | map/codex 独立页面无"当前角色"角标，返回语义不明确 | 独立打开 /map.html 没有联动 | ✅ 已解决（E-6） |
| A-7 | 首屏 9 个"空魂环位"全空，信息价值低、目标不明确 | 初始 G.rings 空则渲染 9 个 empty 卡 | ✅ 已解决（E-7） |
| A-8 | 主线与魂环目标缺少可行动按钮 | 旧版本 story-status 只有文案 | ✅ 已有能力（E-8 复核通过） |
| A-9 | 移动端左侧状态栏信息层级重，需要紧凑状态栏 | - | ✅ 已存在（E-9 复核通过） |
| B-1 | iframe 消息未校验 origin/source（安全） | `game.html` 消息监听只查 type | ⏳ 待办（P1） |
| B-2 | 主题 token 多套漂移，难维护 | game.html/map/codex 各一份内联 token | ⏳ 待办（P1） |
| B-3 | 后端存档 list 无 `gameMode` 字段过滤，旧 Canvas 存档会混入 | `server.js` list 全量返回 | ⏳ 待办（P1） |

## 四、后续开发方向（待办，按优先级）

### P1（建议尽快做）
1. **后端 `gameMode` 字段 + 存档列表过滤**：在存档对象上统一写入 `gameMode`，`/api/player/list` 两端按模式过滤，避免旧 Canvas 的存档混入文字版读档列表。
2. **iframe 消息校验统一**去集成 `isTrustedMessage` 校验函数（校验 `e.origin` 是否为本站 & `e.source` 是否为未信任 iframe），替换现有只查 `e.data.type` 的写法；map/codex 的 `.map-ready`/`navigate` 等消息同样处理。
3. **抽共享 tokens.css**：把 game.html 内联的主 token 变量（背景、金色、陶线等）提取为共享 CSS，消灭 map/codex 各自漂移，统一维护。

### P2（体验与稳定性）
4. 文字版存档在传入服务器时校验 `spirit` 结构，读档前失败给出明确文案（已在 game.js 有部分处理，可再完善）。
5. 创建流程的「约 2 分钟」提示保持与整体时长一致，避免预期偏差。
6. 新角色开局时如检测到本地有旧档，增加"将覆盖/新建"的二次确认交互（可选，`resetRoleShell` 已铺垫）。

### 探索（可后置）
7. 移动端首屏进入游戏第一屏的信息密度再收敛（Story 卡片高度）。
8. 图鉴 + 存档联动：按玩家进度点亮词条（较大的改动，需评估，暂缓）。
