## 零、结论速览

游戏架构清晰、防御意识好（安全头、限流、乐观锁、历史版本、Token、CSP、richText 白名单都已就位），
但**鉴权体系存在可被绕过的高危漏洞**：任何能访问服务器的人都能拿到任意玩家存档的写权限。
此外有 **1 处存储型 XSS**、若干**随游玩时长无界增长的存档字段**、以及**一批数值公式/奖励结算不一致**的隐性 bug。

按「部署到公网服务器」的视角，优先级排序如下：

| 级别 | 问题 | 一句话 |
|---|---|---|
| 🔴 P0 | 鉴权可绕过 | `POST /api/player/auth` 不传 `name` 即可给任意 playerId 发 Token |
| 🔴 P0 | 读接口全公开 | `/api/player/list`、`/load`、`/history` 无鉴权，泄露所有玩家存档 |
| 🔴 P0 | 存储型 XSS | 角色名未转义直接进 `v-html`（SceneArea），CSP 又放行 inline |
| 🟠 P1 | 限流失效 | 未设 `trust proxy`，Nginx 后所有请求共享一个限流桶，可被全体锁死 |
| 🟠 P1 | Token/密钥不持久 | `TOKEN_SECRET` 每次随机 + HMAC 从不校验 + token 存内存，重启全登出 |
| 🟠 P1 | 无 HTTPS | nginx 只监听 80，公网明文传输 Token/存档 |
| 🟡 P2 | 存档无界增长 | 地点探索合成事件 id 永久进 `doneEvents/completedEvents/_storyDecisions` |
| 🟡 P2 | 奖励结算不一致 | 战斗胜利但吸环失败 → 整场经验/金币被吞；训练战败走真实战败惩罚 |
| 🟡 P2 | 数值公式 bug | 冷却减免减法/乘法混用、武魂融合 1.65 倍率重复、升级治疗双轨 |
| 🟡 P3 | 性能 | finalStats 每回合重算 4~6 次、地图状态全量重建、dist 混入 ~1.1MB 旧产物 |

## 一、安全漏洞（部署前必修）

### 🔴 S1. 鉴权可绕过：不传名字即可给任意玩家发 Token（Critical）

**文件**：`server.js:240-260`（`/api/player/auth`）

```js
if (fs.existsSync(file)) {
  const data = JSON.parse(fs.readFileSync(file, 'utf8'));
  if (data.name && name && data.name !== name) {   // name 为空时整段跳过
    return res.status(403).json({ error: '名字与存档记录不匹配' });
  }
}
const token = generateToken(playerId);
```

- 请求体只传 `{ playerId }`（不传 `name`）时，`data.name && name` 为假，校验被跳过，直接发 Token。
- 存档不存在时也完全不校验，等于「任何 playerId 都能凭空开户」。
- 即便补上 name 校验也形同虚设：`/api/player/list` 和 `/api/player/load/:playerId` 无鉴权，直接暴露所有人的 `name`，攻击者照抄即可。

**影响**：拿到 Token 后可 `save`（覆盖存档）、`delete`（删除存档）、`restore`（恢复历史）任意玩家。
配合 S9（乐观锁可省略 `expectVersion`），可无冲突直接覆盖。公网下这是**完整的存档接管/破坏**。

**修复**：鉴权不能依赖「知道名字」。最小改动：给 `auth` 增加一个真正的秘密（如 `SAVE_PASSWORD` 环境变量 / 每角色 PIN），
或干脆把写接口限定为「仅本地/内网访问」。同时给 `save` 强制要求 `expectVersion` 参与乐观锁。

---

### 🔴 S2. 读接口全公开，泄露所有玩家存档（High）

**文件**：`server.js:317-332`（load）、`335-364`（history）、`455-463`（list）

三个读接口都没有 `requireAuth`。`load/:playerId` 返回完整存档（含 `_diary` 日记、姓名、等级、魂环等），
`list` 枚举所有玩家，`history` 返回历史版本。任何公网访客无需任何凭据即可拖走所有存档数据。

**影响**：隐私泄露（日记/进度），并为 S1 的鉴权绕过提供「姓名」素材。

**修复**：读接口加 `requireAuth`（或至少 `/load` 与 `/history`），`list` 若需保留公开，只返回去隐私的摘要且不暴露 playerId 之外的敏感字段。对单机自玩，最低限度也应删掉公网暴露路径。

---

### 🔴 S3. 存储型 XSS：角色名未转义进入 `v-html`（High）

**文件**：`frontend/src/components/SceneArea.vue:14,125`（`eventText`/`resultDisplayText`）

```js
const eventText = computed(() =>
  texts.join('<br/><br/>')
    .replace(/\{name\}/g, props.playerName)   // 用户输入直接拼进 v-html
    .replace(/\{spirit\}/g, props.spiritName))
```

- `playerName` 是用户输入（创建页仅 `maxlength=8`，且**服务端对存档 `name` 零校验**，可被绕过到任意长度）。
- 事件文本里的 `{name}` 占位符被替换为原始 name 后经 `v-html` 渲染，`<img src=x onerror=...>` 会执行。
- `engine/rules.js` 已有 `richText()`（先转义再白名单恢复），但这里**没有调用**——`arrivalSummary` 路径有 richText，eventText/resultText 漏了。
- CSP `script-src 'self' 'unsafe-inline'`（`server.js:30`）进一步放大了危害：注入的内联脚本会被放行。

**影响**：一条「恶意名字的存档」被受害者加载后即可在受害者浏览器执行脚本 → 窃取 `sessionStorage` 里的 Token → 账户接管。
攻击者通过 S1 的鉴权绕过直接往受害者存档里写入恶意 name 即可完成链路（公网场景）。

**修复**：
1. 渲染前对 name 做转义（把 `props.playerName` 先过 `escapeHtml`，或对拼接后的整串过 `richText`）。
2. 服务端对 `data.name` 加长度/字符白名单（如 `^[\u4e00-\u9fa5A-Za-z0-9·]{1,16}$`）。
3. 移除 CSP 里不必要的 `'unsafe-inline'`（`dist/index.html` 无任何内联脚本，纯外链 module）。

### 🟠 S4. 未设 `trust proxy`：限流在 Nginx 后完全失效（High）

**文件**：`server.js`（无 `app.set('trust proxy', ...)`）、`deploy/nginx-douluo.conf:35-36,49-50`

Nginx 把 `X-Real-IP` / `X-Forwarded-For` 传给了 Express，但 Express 未启用 `trust proxy`，因此 `req.ip` 恒为 Nginx 的 `127.0.0.1`。
`rateLimit()`（`server.js:42-69`）以 `label:ip` 为桶键 → **所有玩家共享同一个限流桶**：

- 任意一个人短时间刷满 60 次/分（或 10 次/分存档），全服其他人一起被 429 锁死（自 DoS）。
- 反过来，限流也没有起到「按人防滥用」的作用。

**修复**：`app.set('trust proxy', 1)`（只信任一层 Nginx），并按 `req.ip` 正确分桶。
若改成 `trust proxy`，务必只在 Nginx 独占接入时设为 `1`，避免公网直连时被 `X-Forwarded-For` 伪造绕过限流。

---

### 🟠 S5. Token 不持久 + HMAC 从不校验（Medium）

**文件**：`server.js:19,147-165`

- `TOKEN_SECRET = process.env.TOKEN_SECRET || randomBytes(32)`：默认每次启动随机。docker-compose 也未注入 `TOKEN_SECRET`。
- `generateToken` 算出的 HMAC 只是拼在 token 里当装饰：`validateToken` **只查内存 Map，从不验证 HMAC**。
- token 存内存 `tokenStore`，容器重启全部失效，所有玩家被登出。

**影响**：即便你给 compose 配了 `TOKEN_SECRET` 指望「重启不掉线」，也无效——因为 HMAC 根本没被校验。

**修复**：二选一——
1. 无状态方案（推荐）：`validateToken` 改为「重新计算 HMAC 并比对」，持久化 `TOKEN_SECRET`（compose 注入），删除内存 Map。
2. 有状态方案：接受重启登出，但至少删掉误导性的 HMAC 拼接与 `TOKEN_SECRET`，或明确注释。

---

### 🟠 S6. 无 HTTPS（Medium）

**文件**：`deploy/nginx-douluo.conf:1-3`（仅 `listen 80`）

公网下 Token（`x-auth-token` 头）与存档内容明文传输，可被中间人窃取。`X-Forwarded-Proto` 已设置但无 `ssl_certificate` 块。

**修复**：接入 certbot（Let's Encrypt）配置 443，并把 80 重定向到 443；`server.js` 可加 HSTS 头。

---

### 🟡 S7. 调试页面打进生产（Low）

**文件**：`public/debug-saves.html`（同时被 vite `publicDir` 复制进 `frontend/dist/debug-saves.html`）

「存档恢复工具」暴露在 `/debug-saves.html`：列出本机 localStorage、拉取全部服务器存档列表、粘贴任意 JSON 写回存档。
对自玩是工具，但一旦公网可访问就是信息泄露 + 存档篡改入口。

**修复**：生产构建删除该文件，或将其移到只有自己可访问的路径/加访问控制。

---

### 🟡 S8. `restore` 未校验 version 为整数（Low）

**文件**：`server.js:373-375`

```js
if (typeof version !== 'number' || version < 0) return 400;
```

浮点（`1.5`）、超大值（`1e21`）都能通过，`v${version}.json` 拼出非法文件名。当前 `path.resolve` + `startsWith` 前缀校验兜住了路径穿越，无直接危害，但属不严谨。

**修复**：加 `Number.isInteger(version) && version >= 0`。

---

### 🟡 S9. 乐观锁可被省略（Low，S1 的放大器）

**文件**：`server.js:283`

`if (expectVersion !== undefined && expectVersion !== currentVersion)` —— 客户端不传 `expectVersion` 就**跳过冲突检查直接覆盖**。
前端永远传版本号，但恶意客户端（拿到 S1 的 Token 后）可以不传，从而无视乐观锁覆盖他人存档。

**修复**：对已存在的存档强制要求 `expectVersion === currentVersion`（首次写入才允许省略）。

---

### ℹ️ S10. 信息披露（Info）

`/api/health`（`server.js:219-237`）返回存档数、内存、uptime；`/api/player/list` 返回全部玩家摘要。自玩可接受，公网建议收敛。

`frontend/dist/assets` 同时存在 `map_bg_v2.webp`（584KB）与 `map_bg.jpg`（197KB）两个版本；另有 `ring_codex_master.jpg` 214KB、`beast_codex_master.jpg` 168KB。同图两个格式并存且 webp 反而更大（webp 可能是未二次压缩的母本）。

### P3. 事件/战斗热路径重复计算（Medium）

- `finalStats()`/`getMaxSpiritPower()` 每回合 4~6 次全量重算（含遍历魂环、魂骨 ×4 reduce、称号/阵法/NPC 好感循环）→ 用 computed 缓存。
- `buildMapState` 每次地图渲染整体重建 destinationPlan/探索状态/BFS → 按地点缓存并只失效变更项。
- `checkAchievements` 单次刷新重复调 `combatPower()` 3-4 次 → 先算一次复用。
- 事件加权抽取每次重建 O(Σweight) 数组 → 累加区间 O(n) 一次遍历。

### P4. 后端同步 IO 仍阻塞事件循环（Low-Medium）

`/api/player/save`、`/load`、`archiveCurrentSave`（`server.js:196-215,279-303,322`）仍用 `readFileSync`/`writeFileSync`/`readdirSync`。M3 已把 list 异步化，但 save/load/archive 仍是同步。单机可接受，存档多/并发高时会阻塞所有请求。

**修复**：save/load/archive 改用 `fs/promises`；`archiveCurrentSave` 的归档可在写档后异步执行（不阻塞响应）。

### P5. `/api/player/list` 读整份存档取摘要（Low）

`loadPlayerList`（`server.js:421-452`）逐个 `JSON.parse` 完整存档只为取 name/level/spirit。已有 45s TTL 缓存 + 写失效，短期够用；长期可改为「写档时顺带写一份 `_summary` 元数据」或独立索引表。
