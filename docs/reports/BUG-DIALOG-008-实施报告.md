# BUG-DIALOG-008 实施与审查报告

## 1. 用户规则与边界

- 先天魂力 90 对应起始 Lv.9，先天满魂力 100 对应起始 Lv.10。
- 满魂力只立即解锁第一魂环猎取资格，不自动获得魂环、魂技或猎环奖励。
- 本轮不改变魂环候选池与风险收益；该内容属于 BUG-DIALOG-011。

## 2. 已确认源码事实

- `initNewCharacter()` 过去无条件写入 `player.level = 1`，这是创建后等级错误的直接根因。
- 觉醒结果属性预览也固定以等级 1 调用 `calcPreview()`；即使只修改存档等级，创建页属性仍会与进入游戏后的最终属性不一致。
- 第一魂环门槛已经由 `pendingRingLv = 10` 表示，猎环结算也已有“未获得魂环前等级封顶、经验暂存”规则，无需新造第二套成长系统。

## 3. 实现方案

- 新增唯一纯函数 `initialLevelFromInnatePower()`：先天魂力每完整 10 点换算 1 级，结果钳制在 Lv.1～10；因此 75→7、90～99→9、100→10。
- 新角色等级使用该结果；创建页属性预览同步使用同一等级，避免预览/落盘分叉。
- Lv.10 初始化 `event.pendingRingLv = 10`、延迟为 0，但 `rings` 与 `skills` 仍为空数组。
- 觉醒结果新增“起始等级 Lv.X”；Lv.10 额外展示“第一魂环猎取资格已解锁 · 当前尚未获得魂环”，明确资格与奖励的区别。
- 不迁移或重算旧存档等级，避免擅自改变既有角色成长记录。

## 5. 测试与实际效果

- 新增 3 项单测：换算边界；100→Lv.10 且零魂环/零魂技、pending=10；90→Lv.9 且不提前解锁。
- 前端定向/全量测试通过 133/133；原有使用先天魂力 50 创建角色的战斗、事件、签到、人物和存档测试均通过，证明等级换算没有破坏对应流程。
- 真实 Chrome 通过既有神级武魂自选链生成 100 点满魂力，结果页实际显示“起始等级 Lv.10”和“第一魂环猎取资格已解锁 · 当前尚未获得魂环”；预览属性以 Lv.10 计算，页面无横向裁切或控制台错误。
- 改前对照：`docs/local/bug-dialog-004/bg004-b-1920-result-full.png`（没有起始等级和猎环资格说明）。
- 改后实图：`docs/local/bug-dialog-008/bg008-after-1920-full-power-level-10.png`。

## 6. 兼容性与剩余风险

- 无新存档字段；沿用 `level` 与 `pendingRingLv`。
- 先天魂力非整十值采用向下取完整等级，例如 75→Lv.7；这与用户明确的 90→9、100→10 保持同一比例规则。
- 满魂力角色仍会经历既有序章/早年剧情；“猎环目标始终可见和可挂起”将在 BUG-DIALOG-012 单独完成，本轮只保证资格状态从创建落盘时已经生效。
- 最终 `ACCEPTED` 由唯一 BUG 清单记录，本报告不预写结论。
