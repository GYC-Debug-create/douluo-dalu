## 三、C 存档系统 · 发现的问题

### C-a.（P1｜舒适度·安全感）云端静默覆盖，无"冲突确认"

- **现象**：`loadPlayer`（game.js:3169）读服务器档后直接把 `G` 写进 localStorage 主键，再被
  `saveLocal()`/自动存档立即覆盖回服务器（game.js:3186-3193）。本地与云端时间戳不一致时，
  没有任何比对与确认——玩家在哪个更旧、哪个更新、哪个是当前会话的档，完全靠猜。
  `openSaveList` 中同一个 `playerId` 会出现"读取本地"和"读取云端"两行（game.js:3110），若
  本地已 happy 玩到 20 级、云端还是旧档，误点"读取云端"会直接把本地进度吞掉且无提示。
- **建议**：读取前比对 `_saveTime`（本地）与 `lastSave`（云端），差异时给一行：
  `本地更晚（MM-DD HH:mm）· 云端更早（…）→ 确认覆盖按回云端」或「保留本地」`，并高亮危险动作。
  过后再用 toast 确认 `已切换档案`。

### C-b.（P2 安全感）自动云存档在大压力节点没有"可靠刷盘"

- **现象**：`beforeunload` 只 `saveLocal`（game.js 6164），不推服务器；自动云存档默认 60s
  一条 interval（game.js:1421-1423），中间任意一次设备异常（崩溃/杀进程/断电）丢的就是这 60s
  刚发生但未推云的内容。对"怕丢档"的玩家，这个窗口是零信任的来源。
- **建议**：在 `visibilitychange`/`pagehide` 触发 `saveServer(true)`；同时把 `startAutoSave`
  的分钟做一次"增量节流 + 失败重试"（比如失败后 10s 重推一次，在线检测 `navigator.onLine`）。
- 补充：手动"立即保存"已等服务器返回是正确的（game.js:5077）。

### C-c.（P2·舒适度）存档"大小/时间"无感知

- **现象**：保存是静默动作，状态栏没有"最近存档"时间戳；玩家对"自动存档兜底了吗"没有可自查的信号；
  存盘超过 localStorage 配额（5MB）时 `saveLocal` 只 `console.error`，玩家完全无感。
- **建议**：状态栏加一行微小的 `⌁ HH:MM 已存档`（到秒），并在写失败时 `toast('自动存档失败…')`；
  导出/导入保持一致上限（现有 import 5MB > 服务器 2MB，防止导入成功但云存失败的诡异状态）。

### C-d.（P3·可考虑）单本地槽 + 多云端 = 易误删

- 本地删除会把 `LS_KEY` 和全部备份链一口气 pomaz；云端删除没有二次输入确认弹窗。可考虑对
  云端删除改为"要输入角色名/playerId 才能删"，避免手滑把辛苦打的云端档删掉。

## 四、D 结论 · 发现手感

### D-a.（P2）升级即刻"满血满魂力"与成长经济不匹配

- `gainExp` 有升级时无条件 `G.hp = finalStats().maxHp; spiritPower=满`（game.js:1458-1462）。
  这本身是令人高兴的设计（新手友好），但会导致一个反直觉时刻：**回合制下利用"边上很小的一格经验"
  反复刷满血，让"濒死→顿悟"型事件与治疗/商店道具失去存在感**。
- 建议：保留"升级回血"，但收紧为"升级回 30~50% 缺口 + 满魂力"，或让升级回血只发生在≥2级的大跳时。

### D-b.（P2·操作舒适）技能树无"重置"，点错永久损失

- 整个 `openSkillTree`（game.js:4422）只有"点就学、学了就存"，没有撤销/重置/退款。
  树本身 Lv.90 才能点满，单点成本最高 3 点（spi5 等），对休闲玩家一旦手滑，整档困住。
- **建议**：至少加"重置（退还已用点，不可在战斗中）"按钮 + 二次确认；或显示"该节点无法后悔"。

### D-c.（P2）属性"合成终值"但"辣根分开"，玩家看不出 buff 来源

- `finalStats` 汇总了武器/称号/技能树/锻造/NPC 加成，但状态面板只显示"攻击多少"（≈终值），
  玩家改变任何一个养成模块后不知道"哦，是技能树让我涨了 15%"。
- **建议**：右键/看详情分开呈现"基础 + 装备 + 称号 + 技能树 + 锻造"各档（可放属性面板小字）。

### D-d.（P3）100 级后经验直接清空

- `advanceExperience` 里 `level>=100` 时 `exp=0·overflow=0`（game-rules.js:170-173），
  之后所有经验奖励直接蒸发，且无提示。满级玩家很容易愣住"我经验条怎么归零了？"。
- **建议**：满级后转成金币/命运点，或在 UI 顶部提示"已满级，经验已转换为…"。

### D-e.（P3）修炼/锻造的确认级别不一致

- 修炼点击即消费无确认（可接受）；**锻造在成功率 70% 时失败会白吃 5 块高级碎片（至尊骨这个）**，
  却只有一个 `toast('锻造失败！材料已消耗……')`，没有二次确认，也没有"失败回退一块材料"。
- **建议**：给 role="confirm" 的高消耗锻造（`goldCost≥600` 或 `successRate`）前弹一次质问；
  失败时可返还 1/2 的材料（受现实信心）。

### D-f.（P4）挑战塔重试零成本 = "凹过塔"

- `challengeTowerFloor` 失败无冷却无代价，同一层可无限重试（game.js:5335-5354）。
  这在"休闲战斗"里算甜，但会让塔层的难度数字形同虚设，且奖励一次性 GET，重复挑战无收获。
- 可选：设置"每层首次通给大奖、重复通只给少量金币或碎片"，让塔仍有精通奖励而不退坑。

### D-g（体验缺口）每日签到 7 日循环有状态但用户视角触感弱

- 规律正确（连续 7 天 → 命运+1），但没有"今天已签/明天领什么/断签重置"的强提示。
  建议将 7 天奖励做成一行明确进度条（今天第 X 天，明天领 Y 金币）。
