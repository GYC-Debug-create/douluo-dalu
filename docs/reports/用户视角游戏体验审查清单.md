## 一、我采用的玩家判断标准

玩家不会因为“代码里有函数”就认为功能存在。对玩家而言，一个功能必须完成以下闭环：

> 看得见入口 → 知道为什么用 → 能够进入 → 操作有明确结果 → 结果改变角色或剧情 → 后续能感知到变化。

本次重点检查了：

- 新玩家从创建角色到第一次正式剧情的首通流程
- 等级、经验、魂环和魂技的成长闭环
- 正式战斗、魂环猎取和失败/胜利反馈
- 地图、旅行、地点专属事件和探索状态
- NPC 结识、好感、互动和关系奖励
- 商店、背包、金币、魂骨锻造和任务
- 成就、称号、技能树、挑战塔、签到和结局
- 存档、重开、快捷键、帮助文本和移动端操作

### 结论等级

- **已确认硬问题**：从当前代码或数据可以直接证明会出现错误、无效结果、永久不可达或严重误导。
- **高风险体验问题**：代码逻辑高度支持该结论，但建议你再按玩家路径确认是否符合原设计。
- **设计取舍问题**：不一定是程序错误，但会明显影响玩家理解、节奏或沉浸感，建议确认方向。

# 三、P0：会破坏规则可信度或主线闭环的问题

## UX-001：我为什么已经在史莱克学院了？

**等级：P0｜已确认硬问题**

### 玩家路径

1. 创建名字。
2. 选择出身。
3. 完成武魂觉醒。
4. 看完序章和三段早年经历。
5. 第一次正式事件出现“第一堂课”。

### 玩家感受

我会发现自己没有经历任何以下过程：

- 武魂殿登记
- 先天魂力评定
- 学院推荐或录取
- 入学资格确认
- 报到、分班、住宿
- 第一次见到老师和同学

但第一堂课直接写成“你抱着崭新的课本找位置坐下”，还直接认识大师。这会让我觉得角色不是“进入了世界”，而是被系统传送到了一个默认场景。

### 代码依据

- `public/game.js:602-651` 创建角色时虽然保存了 `_registeredAtHall`、`_enrollmentComplete`、`_academyRecommendation` 等字段，但它们只是默认字段。
- `public/game.js:2368-2455` 进入游戏后直接播放早年经历，完成后调用 `nextEvent()`，没有按这些字段建立入学流程。
- `public/game-data.js:262-289` 的 `first_class` 直接以角色已经在教室为前提。

### 用户影响

- 出身选择没有真正决定角色去哪所学院。
- 海神岛渔村、边境小城、武魂城世家等出身都默认被送进史莱克学院。
- 玩家无法解释自己为什么具备进入史莱克学院的资格。
- 后续人物关系、学院事件、地图位置都缺少起点因果。

### 我希望看到的闭环

`出生/家庭 → 六岁觉醒 → 武魂殿登记 → 魂力测试 → 推荐或自选学院 → 入学报到 → 初识老师/同学 → 第一堂课`。

### 建议确认

**建议修复。** 如果产品确实只想做“觉醒后直接爽玩”，也应该在序章中明确一句“你已通过测试并被史莱克学院录取”，而不是让玩家自己猜。

## UX-002：我明明获得了生命，为什么反而掉血？

**等级：P0｜已确认硬问题**

### 玩家看到的内容

很多事件文本会写：

- “恢复生命”
- “身体素质提升”
- “获得生命力”
- “神体淬炼后更强韧”

玩家自然会把 `hp: 20` 理解为增加生命或恢复生命。

### 实际逻辑

`public/game.js:2030-2079` 中，`r.hp` 统一走生命值当前值变更：

```js
G.hp = Math.max(1, Math.min(fs.maxHp, G.hp + val));
```

但 `getSpiritBonus('hp')` 会把武魂的生命特质倍率也乘进去。对“强攻系”角色，特质中包含“狂暴”，而 `TRAIT_BONUS` 中：

```js
狂暴: { attack: 1.5, hp: -0.5 }
```

因此正数生命奖励可能变成负数。例如：

```text
事件 hp +20 × 狂暴 hp -0.5 = -10
```

### 更严重的表现

`public/game-events-expanded.js` 中至少有三处同一结果对象里重复写 `hp`：

- `adv_stat_01`：`hp:20, hp:-10`
- `god_stat_01`：`hp:100, hp:-50`
- `ma_more_03`：`hp:50, hp:-30`

JavaScript 最终只保留后一个字段，因此玩家看到的文本和作者原本想表达的“获得生命、同时承受损伤”无法同时成立。

### 玩家影响

- 事件结果与常识相反。
- 玩家会认为强攻系武魂有隐藏惩罚，但界面没有解释。
- 同一个 `hp` 字段同时承担“当前生命恢复”“最大生命永久加成”“承受伤害”三个语义，规则不可读。

### 建议确认

**必须修复。** 建议拆成：

- `maxHp`：永久增加最大生命
- `heal`：恢复当前生命
- `damage`：扣除当前生命
- `hp`：不再允许同时承担多个语义

武魂特质对“生命恢复量”和“最大生命”也应分别定义倍率，不能用负的 `hp` 倍率直接反转治疗。

## UX-003：魂环选择界面告诉我的数值，和最后到账的数值不是一套

**等级：P0｜已确认硬问题**

### 玩家路径

1. 到达魂环门槛。
2. 看到白、黄、紫、黑、红等年份选择。
3. 对比攻击、防御、生命加成和风险。
4. 猎杀魂兽并吸收魂环。

### 玩家看到的预览

`public/game.js:1430-1485` 中 `getRingTierOptions()` 使用的是一套简化数据：

```js
white:  { attack:3, defense:2, hp:20 }
yellow: { attack:6, defense:4, hp:50 }
purple: { attack:12, defense:8, hp:120 }
black:  { attack:25, defense:16, hp:280 }
red:    { attack:50, defense:32, hp:600 }
```

### 实际到账

`public/game.js:1290-1310` 的 `makeRing()` 使用 `DATA.rings` 中另一套数据。例如图鉴里：

- 白环攻击 +2、防御 +1、生命 +20
- 黄环攻击 +8、防御 +5、生命 +80
- 紫环攻击 +25、防御 +15、生命 +200
- 黑环攻击 +80、防御 +50、生命 +600
- 红环攻击 +250、防御 +160、生命 +1800

而 `makeRing()` 还会读取 `def.statBonus` 生成最终魂环。

### 玩家影响

我无法根据界面做出可信选择：

- 预览显示紫环攻击 +12，实际到账可能是 +25。
- 预览显示红环生命 +600，实际可能是 +1800。
- 选择风险和收益时，我是在对错误数据做决策。

### 建议确认

**必须修复。** 预览应直接从同一个 ring definition 派生，不能在 `getRingTierOptions()` 里再维护一份平行数值。

## UX-004：我选择了不同魂兽，但最后得到的魂技主要只由武魂类型决定

**等级：P0｜已确认硬问题**

### 玩家预期

魂环猎取界面会让我选择：

- 灵鹿
- 毒蛛
- 风灵燕
- 烈焰虎
- 人面魔蛛
- 暗金恐爪熊等

每个魂兽都有名称、属性、栖息地和战斗数值。玩家自然会认为不同魂兽会带来不同魂技。

### 实际逻辑

`public/game.js:1290-1308`：

- `makeRing()` 只接收 `ringId` 和 `sourceName`。
- 魂技名称由 `genSkillName()` 生成。
- `genSkillName()` 主要根据 `G.spirit.type` 从 `SKILL_PREFIX` 选择前缀，再随机选择动作字。

也就是说，魂兽名称主要作为 `source` 写进展示，不能稳定决定魂技的元素、效果、技能名或机制。

### 玩家影响

- 选择魂兽只是选择一个战斗对手和一个来源名字。
- “毒蛛”和“风灵燕”可能给出同类魂技。
- 玩家无法形成“我为了控制选择蛛类、为了速度选择飞禽”的构筑策略。
- 魂兽图鉴的特性没有转化为实际玩法。

### 建议确认

**必须修复或缩减入口。** 至少让魂兽的 `element`、`specialAbility`、`traits` 影响技能效果；如果暂时不做魂兽差异，就不要用四张看起来具有策略意义的魂兽卡误导玩家。

## UX-005：事件 ID 重复，剧情状态会互相污染

**等级：P0｜已确认硬问题**

### 已确认数据

运行时加载后的事件库中至少存在以下重复 ID：

- `adv_more_01` 至 `adv_more_06`
- `ma_more_01` 至 `ma_more_04`
- `god_more_01` 至 `god_more_03`

每个重复两次。

### 代码依据

- `public/game-events-expanded.js` 追加事件时使用了与前面已存在事件相同的 ID。
- `public/game.js:335-344` 的 `normalizeLoadedEvents()` 会把重复事件自动改名为 `id__2`，这虽然避免了数组完全同 ID，但会把原始数据问题隐藏起来。
- `public/game.js:1178-1188` 的 `_recentEvents` 按 ID 做近期冷却。
- `public/game.js:1810-1825` 的 `unique` 事件按 ID 判断是否完成。
- `public/game.js:2080-2090` 的剧情选择记录也按事件 ID 写入。

### 玩家可能遇到的现象

- 同名事件出现两次，但玩家不知道两次是否有区别。
- 一次完成后，另一个副本可能仍然出现，或两份事件分别进入冷却。
- 日志和选择记录出现相同名称但不同内部后缀的事件。
- 成就、连锁事件、事件完成状态可能对同名事件给出不一致判断。

### 建议确认

**必须修复。** 数据校验应该直接拒绝重复 ID，而不是在运行时静默加后缀。每个事件必须拥有明确、唯一、稳定的身份。

## UX-006：大量事件的阶段和等级互相矛盾，内容会被永久过滤

**等级：P0｜已确认硬问题**

### 已确认规模

当前事件库抽样显示至少 **82 个事件**存在如下冲突：

- `phase: 'adventure'`，但 `minLevel >= 19`
- `phase: 'master'`，但 `minLevel > 40`
- `phase: 'academy'`，但 `minLevel > 6`

示例：

- `sp_bs_03`：`adventure + minLevel 25`
- `ma_gold_01`：`master + minLevel 42`
- `ac_extra_05`：`academy + minLevel 8`
- `ma_more_04`：`master + minLevel 58`

### 代码依据

`public/game.js:1810-1825` 的 `availableEvents()` 同时要求：

```js
e.phase === currentPhase()
G.level >= e.minLevel
```

`currentPhase()` 把：

- Lv.1-6 归入 `academy`
- Lv.7-18 归入 `adventure`
- Lv.19-40 归入 `master`
- Lv.41+ 归入 `god`

因此 `adventure + minLevel 25` 的事件永远不会在 Lv.25 出现，因为那时当前阶段已经是 `master`。

### 玩家影响

- 事件看起来写了等级门槛，但实际根本不会出现。
- 玩家会误以为自己运气差，继续重复点击等待。
- 武魂专属故事、命运路线事件和大段扩展内容可能在错误阶段永久消失。

### 建议确认

**必须修复。** 只能选一种权威规则：

- 用等级决定阶段，数据中的阶段自动校正；或
- 用章节/主线状态决定阶段，等级只是额外条件。

不要让两个字段同时作为硬过滤器但没有数据校验约束。

## UX-007：地图、地点百科和剧情事件对“同一个地方”的叫法不一致

**等级：P0｜已确认硬问题**

### 已确认的三套标识

1. 地图 `map-data.json` 使用规范 ID，例如 `shrek_academy`、`star_duo_outer`。
2. 地点百科 `location-codex.json` 使用中文名作为 ID，例如 `史莱克学院`、`星斗大森林`。
3. 事件使用大量子地点文本，例如：
   - `史莱克学院·教室`
   - `学院·清水湖`
   - `野外·月圆之夜`
   - `深山·无名洞府`
   - `天斗城·地下赌场`

### 代码依据

- `public/game.js:1732-1808` 通过正则和别名猜测事件地点。
- `public/game.js:1803-1808` 如果事件地点无法识别，就直接返回 `true`，等于允许该事件在任何地点出现。

- `game.js` 和 `game-visual.js` 分别监听快捷键/音频状态，玩家无法知道两者是否是同一状态。

### 玩家影响

我打开帮助学习快捷键后，不会知道 V；我按 M 以外的方式静音后，也不确定设置页的“已开启/已关闭”是否同步。

### 建议确认

统一一份快捷键定义并由帮助、设置提示、监听器共同生成；音频按钮、V 键、设置开关共用一个状态源。

## UX-023：手机上状态栏默认折叠，我看不到魂环和成长状态

**等级：P2｜设计取舍问题**

`bindUI()` 在 `window.innerWidth <= 1024` 时会自动触发 `statusToggle.click()`，导致移动端进入游戏时状态栏默认收起。

玩家进入主游戏后首先看到的是剧情，但看不到：

- 当前等级
- HP/魂力
- 经验/魂环门槛
- 魂环数量
- 金币和命运值

这对需要频繁做成长决策的文字 RPG 不利。尤其在魂环门槛、战斗和购买道具前，玩家需要先手动展开状态栏。

### 建议确认

移动端可以默认折叠，但应在剧情区固定显示一个简短状态条，例如：

`Lv.9 · HP 120/180 · 魂力 80/120 · 第1魂环待猎取`

---

## UX-024：宽屏剧情区域仍可能显得偏左、内容密度不足

**等级：P2｜视觉体验问题**

当前 `public/game.html:600-606` 在大屏下将剧情内容、正文和选项分别限制为不同最大宽度：

- 场景子元素最大约 1680px
- 正文最大 1100px
- 选项最大 1280px
- 场景图片另有最大高度限制

这会导致图片、文字和选项的边界不一致。用户在 1920px 宽屏上可能看到剧情图片和按钮集中在左/中部，而右侧留白较明显。

### 建议确认

不是简单把所有内容拉满，而是确定一个统一的剧情内容网格：

- 图片宽度
- 正文阅读宽度
- 选项宽度
- 右侧信息留白

让图片与下方选项拥有清晰的共同边界。

---

## UX-025：存档管理把本地档、服务器档和备份档混在一起

**等级：P2｜体验风险**

`openSaveList()` 会同时展示：

- 当前本地存档
- 本地备份恢复状态
- 服务器同 ID 存档
- 其他服务器存档

虽然代码已经努力标注“本地”“服务器”“本地备份恢复”，但从玩家视角仍有几个问题：

- 哪一个是最新进度不够直观。
- “读取本地”和“读取云端”并列，玩家可能误选旧版本。
- 删除本地后服务器不会删除，删除服务器后本地仍保留，双端状态容易分叉。
- `saveServer()` 失败时本地成功，但玩家之后看到的云端时间可能落后。

### 建议确认

存档管理应把当前有效版本放在第一位，并明确：

- 最后保存时间
- 来源
- 等级/魂环/金币摘要
- 是否比另一份更新
- 读取后是否覆盖本地
- 删除操作影响哪一份

# 六、建议优先确认的用户验收路径

6. 关闭/刷新页面后继续游戏，确认剧情不会被随机切换到不相干地点。

1. 使用强攻系武魂。
2. 选择一个明确写“生命+”的事件。

4. 再选择一个明确写“受伤/扣血”的事件。

3. 打开人物图鉴，确认只有实际相遇的人物被解锁。
4. 前往天斗城、星斗大森林外围和一个未映射地点。
5. 对比抵达后的事件池是否真正发生变化。

## 路径 E：后期完成度

1. 使用高等级存档打开挑战塔、魂骨、技能树、成就、称号和结局条件。
2. 对照帮助文案逐项点击。
3. 记录“说明存在但按钮/效果不存在”的功能。
4. 同时满足两个以上结局条件，确认游戏是否解释最终结局优先级。

# 八、最终判断

当前版本不是“功能少”，而是“功能很多，但多个系统没有使用同一套状态和规则”。从玩家视角，最伤害信任的不是某个按钮样式，而是以下几种经历：

- 我选择了一个东西，实际结果不是界面展示的那个东西。
- 我完成了一个目标，但系统没有承认，或者用另一套条件判断。
- 我进入了一个地点，但地点没有改变我能做的事情。
- 我认识了一个人物，但没有真正遇见他。
- 我做了一个选择，但后续世界没有任何可感知变化。
- 我看到很多功能入口，却不知道哪些是当前旅程真正需要的。

因此，当前最需要优先确认的不是继续增加事件数量，而是先统一：

1. **进度规则**：等级、阶段、魂环门槛、主线章节。
2. **身份规则**：地点、NPC、事件 ID、魂兽和魂环。
3. **奖励规则**：永久属性、当前 HP、金币、经验、魂骨和魂技。
4. **可达性规则**：什么条件能进入什么内容，失败后如何恢复。
5. **反馈规则**：玩家做完一件事后，哪里显示结果，后续如何受到影响。

请按编号逐项确认即可，不需要一次性全部接受。
