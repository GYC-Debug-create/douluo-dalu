# 产品全面调研报告(2026-09-12)

> 调研方式:通读历次审查文档 + 分析 data/ 全部 8 个真实玩家存档 + 前端 2 万行结构梳理 + 本地起服全程亲玩(注册→建号→觉醒→序章→猎环→战斗→地图,简单/完整模式对比)。
> 结论先行:**架构和内容量都不缺,缺的是"把核心循环接对"和"让玩家看见游戏的全貌"。当前最大的漏斗损失发生在新手前 10 分钟,最大的内容浪费发生在系统呈现层。**

## 二、P0:亲眼验证的致命问题

### 1. 新号第一次进游戏就弹「存档版本冲突」
全新账号+全新角色,进入 #/game 十秒内弹出三选一冲突框(保留本地/读取云端/覆盖云端)。
根因:首次保存竞速——建号流程已保存出一版,游戏内紧接着的保存仍带着过期的 `expectVersion=0`,服务器 409 即弹框(`frontend/src/composables/useApi.js:94`、`frontend/src/pages/GamePage.vue:349`)。
新玩家面对"云端存档已被更新"的第一反应只可能是困惑。**任何新创建存档不应触发冲突 UI。**

### 2. 序章可能无法续玩,导致"玩了 3.5 小时剧情从未开始"
3/8 真实存档 `_prologueDone:false`、`_recentEvents` 空、`_visitedLocations` 空,但等级 2~7(靠战斗/修炼按钮磨的)。推测:序章中途退出后,「继续冒险」没有恢复序章链,玩家落进一个"事件引擎被门控、只能干磨数值"的死胡同(需复现确认,证据强)。这是漏斗上最大的洞。

### 3. 默认模式把成年玩家当 6 岁小孩
`_simpleMode` 默认 `true`(frontend/src/stores/game.js:30):新玩家默认看到"体力/能量/金魂币"替换词、隐藏商店/任务/成长/人物图鉴/命运值/时段等**一半以上的系统**,且自动代办会悄悄发奖("自动变强 3 次""6 份成长奖励已自动收好",金币 180→480,玩家莫名其妙)。
斗罗 IP 的核心受众不低龄;低龄模式应该是明确选择,而不是默认。

### 4. `{spirit}` 占位符从未被替换,直接显示给玩家
引擎里不存在任何模板填充逻辑;`public/data/spirit-events.json` 有 101 处 `{spirit}`(选项文本实测原样显示:「询问那位{spirit}武魂魂师的故事」);日记里占位符被直接删字(useEventEngine.js:1737)。game-data.js 头部写的"约定 {name}/{spirit}"根本没实现。

### 5. 猎环——正典核心时刻——没有战斗
默认模式下第一魂环:选猎物 → 一段文字 → 直接得环(后台结算的战斗只吐出一条滞后的「战斗胜利!经验+0」toast)。回合制战斗系统(useBattleSystem 1071 行)做得完整,却没接入这条主循环。斗罗的灵魂时刻"猎环"被降级成了点按钮。

## 四、P2:工程与内容结构(决定大改速度)

1. **双版本全量镜像**:frontend/src/data/{game-data,events-expanded}.js 与 public/{game-data.js,game-events-expanded.js} 手工同步,已经漏过一次(commit ecbccc1);legacy 全家桶(game.html 2752 行 + game.js 6546 行 + map/codex)与 Vue 并行维护。任何内容改动都是双倍工作量+漂移风险。
2. **死资产**:public/index.html + js/ 像素原型(HTTP 不可达);debug-saves.html 生产可达;23+ 个 god_* 事件被引擎封存"永不进池";拍卖只有叙事无系统。
3. **无埋点**:连"玩家在哪个事件停了 30 秒"都不知道。
4. **仓库卫生**:根目录 36MB douluo-update-account.tgz、NUL 等杂物;combat-flow.test.js 硬编码读真实玩家存档。
5. **域名/HTTPS 未接**(说明书里已在规划,IP 直访影响传播与信任)。

## 五、大改方向(按优先级)

### 第一批:修漏斗(P0,1~2 天量级)
1. 新建存档 7 天内(或本会话内创建的存档)永不弹冲突框;冲突判定只比较"云比本地新"的场景。
2. 修序章恢复:任何时刻退出,回来必须从序章断点继续;`继续冒险`时若 `_prologueDone:false` 强制回到序章。
3. 引擎级 fillTemplate:事件文本/选项/日记统一替换 {name}/{spirit};补 1 条 validate 规则防回归。
4. 加最小埋点:服务端日志记"事件展示/完成、卡点(同一事件停留>60s)、等级进度",先解决盲人摸象。

### 第二批:补核心循环(大改主战场)
5. **猎环接入战斗**:选猎物 → 真实战斗 → 战斗表现影响吸收成功率(胜得漂亮=高成功率),反噬机制保留。这是斗罗 IP 的灵魂时刻,值得做成招牌体验。
6. **模式重构**:完整模式为默认;首次进入问一句"给小朋友玩吗?";简单模式做成真·儿童版(精简事件池+更短文本+自动战斗),而不是同一套内容换词+藏系统+自动发奖。
7. **数值与呈现重调**:升级节奏放缓、怪有来有回、奖励结算做成结构化卡片(每项一行、有图标)、修正"千级数字"的观感。

### 第三批:让玩家看见游戏的全貌(留存抓手)
8. **旅程总览页**:四阶段进度 + 图鉴收集度 + 成就/称号/结局达成度 + 主线里程碑,替代现在藏在 4 个菜单 16 个弹窗里的散装系统。
9. **日记入口**(冒险日志页),让已产出的 189 条记录产生回访价值。
10. 成就判定挂到升级/战斗结算/事件完成等自然时机;重复事件用"见过即降权"而非重洗。

### 第四批:架构收敛(为上面三批提速)
11. **事件数据单源化**:以 frontend/src/data 为唯一源,构建脚本生成 public 侧(剧情提升计划里已提过,执行它)。
12. **legacy 退役计划**:codex/map 若 Vue 版已对齐则下线 legacy 入口,game.html 直接 301 到 Vue;砍掉像素原型与 debug 页。
13. 域名+HTTPS;仓库清理;测试补一条端到端新手流程(注册→觉醒→序章完成→首个事件)。

---

## 六、一句话总结

这个产品的底子(内容量、测试、地图、美术)远超它给玩家呈现出来的样子;玩家流失不是因为它差,而是因为**开局就弹存档冲突、剧情可能永远不开始、默认被当成小孩、核心的猎环没有战斗**。大改先修漏斗、再接核心循环、最后让系统被看见——不必推倒重来。
