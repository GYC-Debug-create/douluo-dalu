# 《斗罗大陆·武魂觉醒》文字 RPG 用户侧功能问题清单

**整理日期：2026-07-28**  
**审查对象：** 默认入口 `/` 对应的文字 RPG（`public/game.html`）  
**文档用途：** 记录普通玩家实际游玩时会遇到的功能阻断、不可达功能、功能未生效和明显体验问题，供后续修复及其他 AI 复核。

---

## 一、审查边界

本清单只讨论当前正式主线——文字 RPG。

### 明确不列为问题的内容

1. **无限次重新觉醒武魂**是开发者有意保留的爽玩功能，不需要限制，不作为漏洞或体验问题。
2. `public/index.html` 与 `public/js/` 下的 Canvas 移动打怪版属于下一版本的个人测试原型，不纳入当前用户体验评价。
3. 本文不讨论版权、商业化、美术来源和后端网络攻击问题。
4. 本文不要求删除尚未完成的代码，只判断这些功能对当前普通玩家是否真实可用。

### 结论标记

- **静态确认：** 已能从当前调用关系和代码逻辑确认。
- **运行复现：** 已通过实际运行或接口操作看到现象。
- **建议浏览器复核：** 代码上高度可疑，但仍建议使用全新浏览器环境走完整流程确认最终视觉表现。

---

# 二、玩家侧总览

当前文字 RPG 已经具备角色创建、武魂觉醒、剧情选择、升级、魂环、图鉴、基础商店、修炼、签到、部分技能树、称号和普通结局等内容。

但玩家实际游玩时最明显的问题是：

1. **首次新游戏可能在新手引导结束后卡住。**
2. **剧情中的正式战斗并未实现，所有战斗基本都是点击选项后直接判胜。**
3. **很多看起来已经存在的系统只是有按钮和页面，操作后不会真正影响角色。**
4. **人物、关系、锻造、旅行、动态事件等功能，普通玩家几乎无法正常进入或使用。**
5. **大量事件、成就、任务、称号和特殊结局没有自然达成路径。**
6. **部分功能会直接报错或污染玩家状态，例如统计面板和魂环反噬。**

# 四、会直接阻断玩家的功能问题

## UX-001：首次新游戏可能在新手引导结束后卡住

**优先级：P0**  
**结论：静态确认，建议使用无痕窗口运行复核**

### 玩家操作路径

1. 使用从未玩过游戏的浏览器打开 `/`。
2. 创建角色并完成武魂觉醒。
3. 看完序章。
4. 进入新手引导。
5. 点击最后一步，或中途点击“跳过引导”。

### 玩家看到的现象

引导弹窗关闭，但可能没有出现第一段正式剧情，也没有“继续冒险”按钮。玩家不知道下一步应该做什么。

### 正常情况

完成或跳过引导后，应立即进入 `nextEvent()`，显示第一段可选择的剧情。

### 依据

`public/game.js` 中：

- 新游戏序章结束后，如果需要引导，只调用 `startTutorial()`。
- `startTutorial()` 完成和跳过分支只写入 `dldl_tutorial_done`、清理高亮并关闭弹窗。
- 两个分支均没有继续调用 `nextEvent()`。

---

## UX-002：魂环反噬可能产生 `NaN`，并污染角色状态

**优先级：P0**  
**结论：静态确认**

### 玩家操作路径

1. 达到魂环获取等级。
2. 选择风险较高的高年份魂环。
3. 吸收判定失败。

### 玩家看到的现象

可能出现：

- “受到 NaN 点反噬伤害”
- 生命值显示异常
- 血条异常
- 后续保存后生命值变成异常值或 `null`

### 正常情况

反噬应根据玩家当前最大生命计算出确定的整数伤害，最低保留 1 点生命。

### 依据

`public/game.js` 的 `attemptAbsorbRing()` 使用：

```js
G.maxHp
```

但文字版角色并没有稳定保存 `G.maxHp`。实际最大生命来自：

```js
finalStats().maxHp
```

`undefined` 参与乘法后会产生 `NaN`。

---

## UX-003：“统计”按钮无法正常打开

**优先级：P0**  
**结论：静态确认**

### 玩家操作路径

进入主游戏后点击左侧“统计”。

### 玩家看到的现象

按钮看起来可以点击，但统计弹窗无法正常显示，通常表现为点击后没有结果。

### 正常情况

应该显示综合战力、属性、战斗、探索、NPC、魂骨、成就、技能树和挑战塔等统计。

### 依据

`public/game.js` 的 `openStats()` 调用了：

```js
getSpiritElement()
getActiveFormation()
```

当前文字 RPG 脚本中找不到这两个函数的实现，执行到这里会发生错误，后面的 `openModal()` 无法运行。

# 五、核心玩法尚未真正实现

## UX-004：正式剧情中的战斗只是直接判胜

**优先级：P1**  
**结论：静态确认**

### 玩家操作路径

在剧情中选择：

- 迎战魂兽
- 参加擂台战
- 猎杀魂兽
- 挑战强敌
- 决战 Boss

### 玩家看到的现象

没有进入战斗界面，而是直接看到：

> 经过一番激烈的较量，你取得了胜利！

### 玩家无法进行的操作

- 普通攻击
- 释放正式魂技
- 防御
- 使用战斗道具
- 逃跑
- 根据敌人行动做决策
- 被普通敌人击败

### 依据

`public/game.js` 的 `applyChoice()` 检测到 `result.battle` 后，只调用 `renderContinue()` 显示胜利文字，没有启动战斗状态机。

`buildEnemy()` 虽然可以创建敌人，但没有接入正常剧情战斗流程。

### 补充说明

“魂技试用场”是一套独立演示：

- 不属于主线正式战斗
- 不改变真实战斗统计
- 不产生正式掉落
- 不决定主线胜负

因此不能替代正式战斗。

---

## UX-005：战斗事件经验被重复结算，升级速度失控

**优先级：P1**  
**结论：静态确认**

### 玩家看到的现象

选择一次战斗剧情后，等级提升明显过快，可能迅速跨过多个低等级内容和剧情阶段。

### 原因一：同一事件经验结算两次

`applyChoice()` 先执行一次：

```js
if (r.exp) gainExp(r.exp)
```

进入 `r.battle` 分支后又执行一次：

```js
if (r.exp) gainExp(r.exp)
```

### 原因二：所有经验又统一乘以 2.5

`gainExp()` 内还会执行全局 2.5 倍经验。

因此一个配置为 100 经验的战斗事件，在没有其他武魂倍率时，实际可能获得约 500 经验。

### 额外风险

`applyChoice()` 会直接修改事件对象中的 `r.exp`。当武魂经验倍率大于 1 时，重复事件的经验值可能被一次次放大，而不是每次都从原始配置计算。

### 玩家体验影响

- 学院篇过得太快
- 大量低等级事件还没出现就过期
- 成长缺少节奏
- 魂环获取连续触发
- 后期数值快速膨胀

---

## UX-006：正式战斗不会更新胜负和击杀数据

**优先级：P1**  
**结论：静态确认**

### 玩家看到的现象

玩家在剧情中已经“打赢”很多魂兽，但统计和任务仍显示：

- 战斗胜利：0
- 猎杀魂兽：0
- 胜率：0%

### 正常情况

每次正式战斗结束后应该区分：

- 胜利或失败
- 对手是魂兽还是魂师
- 是否为 Boss
- 是否完成击杀

并更新相关统计。

### 影响范围

依赖这些统计的任务、成就、称号和结局都无法自然解锁。

---

## UX-007：元素、状态、连击、自动战斗和 Boss 机制没有接入主线

**优先级：P1**  
**结论：静态确认**

### 界面和帮助中声称存在的内容

- 元素克制
- 元素反应
- 燃烧、中毒、冻结、眩晕等状态
- 连击
- 暴击
- 自动战斗
- 1×、2×、3×倍速
- Boss 阶段
- Boss 怒气与特殊技能

### 玩家实际体验

正式剧情不会进入战斗，因此玩家没有入口使用这些系统。

当前部分相关代码、样式或帮助文字存在，但没有形成普通玩家可以操作的正式玩法。

# 六、玩家难以进入或无法使用的系统

## UX-008：人物无法通过主线自然结识

**优先级：P1**  
**结论：静态确认**

### 玩家看到的现象

点击“人物”后，大量人物显示为“？？？”。点击“关系”后通常显示：

> 尚未结识任何人物。

### 依据

人物解锁依赖 `meetNpc(npcId)`，但当前项目中没有发现主线事件正常调用这个函数。

剧情文字即使写到“遇见唐三”“认识某位人物”，也不会自动写入人物图鉴。

---

## UX-009：NPC 互动一开始就处于冷却，而且无法自然恢复

**优先级：P1**  
**结论：静态确认**

### 玩家操作路径

在已有解锁人物的存档中打开人物详情，尝试：

- 闲谈
- 送礼
- 切磋
- 协助
- 宴请

### 玩家看到的现象

互动按钮从一开始就可能显示“冷却中”。

### 依据

首次互动时：

- 当前游戏时间为 0
- 上次互动时间默认为 0
- 两者差值小于互动冷却时间

因此首次互动就被判定为未冷却完成。

同时 `advanceTime()` 没有接入主线流程，游戏时间不会正常增加，冷却也就无法自然结束。

## UX-010：收集到的魂骨不能作为锻造材料

**优先级：P1**

### 玩家看到的现象

玩家在魂骨图鉴中已经有魂骨，打开锻造仍显示：

# 七、大量已有内容对普通玩家不可达

## UX-015：168 个武魂专属事件没有接入当前事件引擎

**优先级：P1**  
**结论：静态确认**

### 当前数据规模

`public/data/spirit-events.json` 中约有 168 个武魂专属事件。

### 数据格式与当前引擎不一致

这些事件通常使用：

- `title`，而主引擎读取 `name`
- 字符串 `text`，而主引擎要求 `text` 是数组
- 没有 `phase`，而事件筛选必须匹配当前阶段

### 玩家侧影响

这些事件虽然在加载时被加入 `EVENTS`，但因为没有阶段，`availableEvents()` 不会选择它们。

结果是：玩家选择不同武魂后，原本应该出现的大量专属剧情实际上看不到。

---

## UX-016：至少 95 个事件因等级和阶段冲突而永久不可达

## UX-018：技能树技能点没有正确扣除

**优先级：P1**  
**结论：静态确认**

### 玩家看到的现象

学习节点后，技能点消耗显示不正确。玩家可能在技能点实际不足时继续学习多条分支。

### 依据

技能树保存形式为：


# 十、建议修复顺序（按玩家流程）

## P0：先保证玩家能正常开始并且不会坏档

1. 引导完成和跳过后继续调用第一段剧情。
2. 修复魂环反噬使用错误最大生命字段的问题。
3. 补齐统计面板依赖函数，保证按钮可打开。

## P1：打通一条真正的核心循环

优先完成：

```text
剧情遇敌
→ 进入正式战斗
→ 玩家行动
→ 敌人行动
→ 胜利或失败
→ 更新胜负/击杀/Boss记录
→ 发放一次奖励
→ 推进任务、成就和剧情
```

然后再把以下内容接到同一套战斗里：

- 魂技
- 元素
- 状态效果
- 连击和暴击
- 技能树战斗效果
- 阵法
- 战斗道具
- Boss
- 挑战塔

## P1：恢复已有内容的可达性

1. 统一事件的 `name/phase/text/choices` 数据结构。
2. 修正阶段等级范围，让已有事件能够出现。
3. 统一地点 ID。
4. 接入时间推进、动态事件、连锁事件和隐藏地点。
5. 让主线事件真正调用人物结识、地点访问和魂骨获得。

## P1：补齐外围成长系统闭环

1. 统一魂骨与锻造材料。
2. 让锻造成品加入最终属性。
3. 修复 NPC 首次互动和冷却推进。
4. 修复技能点扣除。
5. 让阵法和技能树说明中的效果真实生效。

## P2：清理界面和反馈

1. 合并重复商店和重复背包。
2. 减少主界面同时展示的按钮数量。
3. 解决 `M` 键冲突。
4. 让保存结果基于真实返回值提示。
5. 接入备份恢复。
6. 更新帮助文字，只描述当前真实可用的功能。
7. 在角色名旁显示当前称号。

# 十一、验收建议

每次修复后，至少使用以下三类存档验证：

1. **全新存档：** 检查创建角色、序章、引导和第一事件。
2. **中期存档（约 Lv.20～40）：** 检查战斗、技能树、任务、地图、NPC、魂环和锻造。
3. **后期存档（约 Lv.90～100）：** 检查第九魂环、最终 Boss、成就、称号和结局。

每个功能都必须验证四件事：

1. 玩家能不能进入。
2. 操作后有没有明确反馈。
3. 奖励或状态有没有真正写入。
4. 保存并重新读取后，结果是否仍然存在。
