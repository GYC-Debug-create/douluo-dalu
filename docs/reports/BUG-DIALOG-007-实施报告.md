# BUG-DIALOG-007 实施与审查报告

## 1. 审查范围

- 问题：地图与旅行/地点玩法脱节，快速旅行缺乏实际意义。
- 本轮只处理 BUG-DIALOG-007；隐藏地点解锁条件与线索闭环留给 BUG-DIALOG-009。
- 用户已授权夜间自主决策、实现和验收，不再等待逐项确认。

## 2. 已确认事实

- `public/data/map-data.json` 已为地点提供活动、NPC、开放等级、相邻路线和路程数据，但旧地图详情没有把这些数据转化为“抵达后能做什么”。
- 旧快速旅行收取普通路线两倍金币，并把途中遭遇率从 32% 降到 8%，但显示路程与普通路线完全相同，因此玩家看不到“快”在哪里。
- 抵达后仅在 32%/8% 概率下生成通用途中遭遇；无遭遇时只显示“安顿下来”，目的地活动、武魂、访问历史、当前猎环目标和人物关系没有形成可见反馈。
- 旅行扣费、地点变更、一次世界行动、存档事务回滚和 session 防刷新重掷机制本身已经存在且可用。

## 3. 产品方案

采用“出发前计划—路线价值—抵达后兑现”的闭环：

1. 地点详情新增“抵达后可做”，固定展示首要目标、武魂适配、人物线索、区域评估。
2. 计划只解释已有数据：活动来自地点 `events`，人物来自 `npcs`；结合待猎魂环、武魂类型、是否到访、已结识人物和角色等级进行稳定选择，不新造掉落或世界规则。
3. 首次探索继续使用普通路线（32% 途中遭遇）；重访可快速旅行（8%），快速路线显示路程减半、最低 1 天。金币规则、世界行动次数和存档格式不变。
4. 同一份结构化计划随 pending travel 带回游戏；无遭遇时显示四行抵达线索，有途中遭遇时也在事件开头保留首要目标、人物线索与区域评估。

## 4. 修改文件

- `frontend/src/utils/mapBridge.js`：新增路程换算和目的地计划纯函数；地图状态、旅行结果携带路线差异与计划。
- `frontend/src/pages/MapPage.vue`：向 iframe 同步事件状态，并把计划写入临时旅行结算。
- `public/map.html`：详情面板展示目的地行动卡、路线时间和遭遇率；动态文本转义；390px 可滚动但不横向裁切。
- `frontend/src/pages/GamePage.vue`：普通抵达页展示同一份计划。
- `frontend/src/composables/useEventEngine.js`：途中遭遇页保留抵达计划。
- `frontend/tests/map-travel-value.test.js`：新增 5 项纯函数/事务测试。
- `frontend/browser-smoke.mjs`：在既有真实旅行链路加入首次探索、抵达、快速重访和 390px 验收。

## 5. 自动化与实际游玩证据

- 定向单测：5/5；覆盖快速路程减半、最低 1 天、魂环目标、武魂适配、访问历史、人物关系、路线风险、事务扣费和降级文案。
- 前端测试：130/130（原 125 + 新增 5）。
- 真实 Chrome 已完成：创建角色 → 打开地图 → 选择相邻地点 → 出发前看计划 → 真实扣费抵达 → 抵达页看到计划 → 再开地图 → 选择已访问地点 → 看到快速路线 8% 风险与缩短路程。
- 390×844：详情面板与页面 `scrollWidth <= clientWidth + 1`，按钮、路线说明均可到达。
- 完整烟测仍覆盖 BUG-DIALOG-001～006，控制台、关键网络与页面错误为 0。

## 7. 兼容性与剩余风险

- 未新增永久存档字段；`destinationPlan` 只存在于地图消息和单次 session travel 中。旧 pending travel 没有该字段时保持旧抵达文案。
- 快速路线“天数”是玩家可理解的叙事路程；现有世界时钟仍按一次旅行推进一次行动，避免擅自改动全局成长节奏。
- 地点活动和 NPC 仍来自现有静态数据，后续数据扩充会自动进入计划；本轮不承诺每个地点拥有独立手写事件池。
- 最终 `ACCEPTED` 只写入唯一 BUG 清单，不在本报告预写结论。
