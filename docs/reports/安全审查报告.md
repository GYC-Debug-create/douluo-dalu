# 斗罗大陆 · 武魂觉醒 —— 安全审查报告

**审查日期**: 2026-07-24  
**审查范围**: 全项目（后端 Express 服务器 + 前端 HTML/JS）  
**技术栈**: Node.js + Express 4.19.2 + 原生 JavaScript（无框架）

---

## 执行摘要

本次审查覆盖了后端 `server.js`（Express 服务器）和前端 4 个 HTML 页面（`game.html`、`codex.html`、`map.html`、`index.html`）及对应的 JS 文件。共发现 **1 个严重漏洞、4 个中等风险问题、3 个低风险问题、2 个代码质量/调试遗留问题**。最严重的问题是**路径遍历漏洞**，攻击者可通过构造恶意 `playerId` 参数读写服务器上的任意文件。

## 一、严重漏洞 (Critical)

### [SEC-001] 路径遍历漏洞 —— 玩家存档文件操作

- **规则 ID**: EXPRESS-FILES-001
- **严重程度**: 严重
- **位置**: `server.js` 第 23 行, 第 28-95 行
- **影响**: 攻击者可通过构造包含 `../` 的 `playerId`，在服务器上读取、写入或删除任意 JSON 文件，可能导致敏感数据泄露或数据破坏。

**证据**:

```javascript

// server.js 第 28-44 行 — 保存：直接使用未验证的 playerId

    const { playerId, data } = req.body;

// server.js 第 47-60 行 — 加载：同样问题
app.get('/api/player/load/:playerId', (req, res) => {
    const { playerId } = req.params;

// server.js 第 84-95 行 — 删除：同样问题
app.delete('/api/player/:playerId', (req, res) => {
```

**攻击示例**:
- `POST /api/player/save` 中 `playerId` = `../outside` → 写入 `data/player_../outside.json` → 实际写入 `d:\GYC\project\斗罗大陆\player_../outside.json`
- `GET /api/player/load/../../package.json` → 可能读取 `package.json` 内容
- `playerId` = `../../../../windows/system32/somefile` → 更危险的文件操作

**修复建议**:
```javascript
// 验证 playerId 只包含安全字符
function validatePlayerId(playerId) {
  // 只允许字母、数字、下划线、连字符，长度 1-64
  return /^[a-zA-Z0-9_-]{1,64}$/.test(playerId);
}

// 在路由中使用
app.post('/api/player/save', (req, res) => {
  const { playerId, data } = req.body;
  if (!validatePlayerId(playerId)) {
    return res.status(400).json({ error: '无效的 playerId' });
  }
  // 再归一化路径确保不会逃逸
  const filePath = path.resolve(getPlayerFile(playerId));
  if (!filePath.startsWith(path.resolve(DATA_DIR))) {
    return res.status(400).json({ error: '无效的 playerId' });
  }
  // ... 继续正常流程
});
```

## 二、中等风险 (Medium)

### [SEC-002] 缺少安全响应头

- **规则 ID**: EXPRESS-HEADERS-001
- **严重程度**: 中等
- **位置**: `server.js` 第 12-14 行（中间件区域）
- **影响**: 缺少 `X-Content-Type-Options`、`X-Frame-Options`、CSP 等安全头，浏览器无法获得防护指令，可能被 clickjacking 或 MIME 嗅探攻击利用。

**证据**: `server.js` 中未使用 `helmet()`，未设置任何安全响应头。

```javascript
// server.js 当前
app.use(express.json());
app.use(express.static(path.join(__dirname, 'public')));
// 没有任何安全头设置
```

**修复建议**:
```bash
npm install helmet
```

```javascript
const helmet = require('helmet');
app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'", "'unsafe-inline'", "https://fonts.googleapis.com"],
      styleSrc: ["'self'", "'unsafe-inline'", "https://fonts.googleapis.com"],
      imgSrc: ["'self'", "data:"],
      fontSrc: ["'self'", "https://fonts.gstatic.com"],
    }
  }
}));
```

### [SEC-003] 未禁用 X-Powered-By 头

- **规则 ID**: EXPRESS-FINGERPRINT-001
- **严重程度**: 中等
- **位置**: `server.js` 第 9 行之后
- **影响**: 响应头中暴露 `X-Powered-By: Express`，帮助攻击者识别技术栈并针对性地利用已知漏洞。

**证据**: `server.js` 中未调用 `app.disable('x-powered-by')`。

**修复建议**:
```javascript
// 在 app 创建后立即添加
app.disable('x-powered-by');
```

---

### [SEC-004] 请求体大小未限制

- **规则 ID**: EXPRESS-BODY-001
- **严重程度**: 中等
- **位置**: `server.js` 第 13 行
- **影响**: `express.json()` 未设置 `limit` 参数，攻击者可发送超大 JSON 请求体导致内存耗尽（DoS）。

**证据**:
```javascript
app.use(express.json());  // 未设置 limit 参数
```

**修复建议**:
```javascript
app.use(express.json({ limit: '1mb' }));
```

### [SEC-005] 错误信息泄露服务器内部细节

- **规则 ID**: EXPRESS-ERROR-001
- **严重程度**: 中等
- **位置**: `server.js` 第 42 行, 第 58 行, 第 79 行, 第 93 行
- **影响**: 错误消息中包含 `err.message`（如文件系统路径、内部错误原因），可能泄露服务器路径结构和内部实现细节。

**证据**:
```javascript
res.status(500).json({ error: '保存失败: ' + err.message });  // 第 42 行
res.status(500).json({ error: '加载失败: ' + err.message });  // 第 58 行
res.status(500).json({ error: '获取列表失败: ' + err.message }); // 第 79 行
res.status(500).json({ error: '删除失败: ' + err.message });  // 第 93 行
```

**修复建议**:
```javascript
// 在 server.js 末尾添加统一错误处理中间件
app.use((err, req, res, next) => {
  console.error('服务器错误:', err);
  res.status(500).json({ error: '服务器内部错误，请稍后重试' });
});

// 路由中只记录日志，不返回 err.message
app.post('/api/player/save', (req, res) => {
  try {
    // ...
  } catch (err) {
    console.error('保存失败:', err);
    res.status(500).json({ error: '保存失败，请稍后重试' });
  }
});
```

## 三、低风险 (Low)

### [SEC-006] 前端 CSP 缺失

- **规则 ID**: JS-CSP-001
- **严重程度**: 低
- **位置**: 所有 HTML 文件（`game.html`、`codex.html`、`map.html`、`index.html`）
- **影响**: 前端无 CSP 策略，如果 XSS 漏洞被利用，攻击者可在页面执行任意脚本。由于所有页面均为纯前端渲染且无用户生成内容注入，风险较低，但作为防御纵深仍建议添加。

**证据**: 所有 HTML 文件均无 `<meta http-equiv="Content-Security-Policy">` 标签，服务器也未设置 CSP 头。

**修复建议**: 配合 [SEC-002] 的 helmet 配置即可同时解决。

---

### [SEC-007] 第三方字体资源无完整性校验

- **规则 ID**: JS-SUPPLY-001 / JS-SRI-001
- **严重程度**: 低
- **位置**: `game.html` 第 8 行, `codex.html` 第 8 行, `map.html` 第 8 行
- **影响**: 从 Google Fonts CDN 加载的字体资源无 SRI (Subresource Integrity) 校验，如果 CDN 被入侵或中间人攻击，可能注入恶意字体文件。

**证据**:
```css
@import url('https://fonts.googleapis.com/css2?family=Ma+Shan+Zheng&family=Noto+Serif+SC:wght@400;600;700&display=swap');
```

**修复建议**: 将字体文件下载到本地 `public/assets/fonts/` 目录，使用 `@font-face` 本地引用。

---

### [SEC-008] 游戏数据存储在 localStorage

- **规则 ID**: JS-STORAGE-001
- **严重程度**: 低
- **位置**: `game.js` 第 398 行
- **影响**: 玩家存档数据存储在 `localStorage` 中，如果存在 XSS 漏洞可被读取。但鉴于这是离线文本游戏、无敏感用户数据，实际风险很低。

**证据**:
```javascript
localStorage.setItem(LS_KEY, JSON.stringify(G));
```

**说明**: 作为游戏存档，使用 localStorage 是可接受的。如果未来引入在线排行榜或账号系统，应注意数据隔离。

## 四、代码质量与调试遗留问题

### [BUG-001] 调试遗留：无限重新觉醒次数

- **严重程度**: 低
- **位置**: `game.js` 第 100 行
- **影响**: 玩家可以无限次重新觉醒武魂，破坏了游戏平衡性。

**证据**:
```javascript
let newChar = { name: '', origin: null, spirit: null, redraws: Infinity };
```

**修复建议**: 将 `Infinity` 改为合理的数值（如 `3`）或根据出身条件设置。

---

### [BUG-002] 缺少自定义 404 和错误处理中间件

- **严重程度**: 低
- **位置**: `server.js` 整体
- **影响**: 访问不存在的路由时会返回默认的 Express 404 页面，暴露了框架信息。

**证据**: `server.js` 末尾的 catch-all 路由（第 114 行）会发送 `index.html`：

```javascript
app.get('*', (req, res) => {
  res.sendFile(path.join(__dirname, 'public', 'index.html'));
});
```

这只处理了 GET 请求。对于 POST/PUT/DELETE 等其他方法的 404 情况，没有自定义处理。

**修复建议**: 添加一个通用的 404 中间件：

```javascript
// 在所有路由之后
app.use((req, res) => {
  res.status(404).json({ error: '未找到请求的资源' });
});
```

## 六、正面评价

以下方面项目做得很好：

1. **无 SQL 注入风险** — 项目使用文件系统存储，无数据库操作
2. **无 XSS 高危注入点** — 虽然大量使用 `innerHTML`，但数据来源均为静态 JSON 文件，且使用了 `esc()` 函数做 HTML 转义
3. **无 eval/Function 动态代码执行** — 使用 `setTimeout` 时均为函数引用而非字符串
4. **无 CSRF 风险** — 项目不使用 cookie 认证，属于无状态 API
5. **无第三方 API 密钥泄露** — 代码中未发现硬编码的密钥或 token
6. **Playwright 密码** — 检查 `SECURITY.md` 文件，无可疑内容
7. **无命令注入** — 未使用 `child_process` 或 `exec`
8. **无 SSRF 风险** — 没有用户可控的 URL 请求端点
