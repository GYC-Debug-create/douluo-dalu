## 2. 根因分析（对照源码）

- 原 `doAwaken()` 中 `spiritRevealed` 承担双重职责：既是“已展示过结果”的标记，又充当操作条按钮组的切换开关（`spiritRevealed=false` 显示「开始觉醒」，`=true` 显示「重新觉醒／自选神级／就是它了」）。
- 每次点击「重新觉醒」都会执行 `spiritRevealed.value = false` 再 650ms 后置回 `true`，于是两组按钮在动画期间反复交换，视觉上即“闪断”；
- 每次点击都会新建 50ms 与 650ms 两个计时器且从不清理旧计时器，快速连点时产生多个陈旧回调，界面状态不可预期；
- 快速连点还会把上一帧结果清空（结果区短暂空白），因此修复目标是：快速重抽期间保留旧结果、不切换按钮组、不堆积计时器。

## 3. 方案 B+ 设计

- **状态分离**：`spiritRevealed` 只描述“是否已展示过结果”（首次觉醒仪式专用）；快速重抽期间的输入阶段（`rerollActive`）、安全锁（`stopLocked`）与待展示结果（`pendingResult`）独立管理。
- **固定操作条**：快速重抽期间不切换按钮组（「开始觉醒」仅在首次仪式阶段显示）；「自选神级」「就是它了」只禁用不消失，操作条尺寸恒定不跳动。
- **快速重抽**：停止点击约 250ms（`RAPID_REVEAL_DELAY_MS`）后展示最新结果；期间保留旧结果（仅整体压暗 `brightness(0.55) saturate(0.85)`），并显示绝对定位提示「连续重抽中…／停止点击后显示最新结果」（`role=status`、`aria-live=polite`，不改变结果区与操作条尺寸）。
- **每次点击 = 一次真实抽取 + 一次真实保底累计**：`rerollAwaken()` 与首次觉醒共用同一 `rollSpiritDraw()`（同一品质抽取、同一武魂池、同一先天魂力公式，随机数消耗顺序一致），非神级 `incrementOriginCount`、神级 `resetOriginCount`（只清当前出身）。
- **自动停止**：神级（立即展示并清零当前出身保底）或非神级首次 49→50（立即展示并解锁自选神级）→ 进入约 650ms（`RARE_STOP_HOLD_MS`）安全锁，仅禁用「重新觉醒」以拒绝尾随点击；已 50/50 后继续重抽不重复触发停止；任何情况下不出现 51/50。
- **计时器纪律**：揭示计时器与安全锁计时器各自最多存在一个；每次新点击先 `clearTimeout` 旧计时器；离开步骤、重新选择出身、卸载时全部清理，杜绝陈旧回调改写界面。
- 以上规则以纯函数 `shouldStopRapidReroll(previousPity, nextPity, tier)` 导出：`god` 恒停；非法/缺失计数返回安全值 false；`previousPity < 50 && nextPity >= 50` 时停止。

## 4. 快速重抽实现要点（CreatePage.vue）

- 模板：`.awaken-stage` 增 `is-rerolling` 类与 `:aria-busy`；新增 `.reroll-hint` 提示；「重新觉醒」改为 `@click="rerollAwaken()"` 且 `:disabled="stopLocked"`；「自选神级」「就是它了」`v-else` 分支保持常驻并 `:disabled="rerollActive"`。

## 19. 失败与完整重跑记录

两次 `npm run test:browser` 失败均为**烟测脚本自身场景设计问题，非产品缺陷**，已说明原因并完整重跑通过：

1. **首轮失败**（阶段 C 断言「收敛后应展示最新结果」）：注入的确定性随机序列按每次点击消耗 5 个随机数设计，而 `updatePity` 每次写入草稿会生成随机 `draftId`（`creation-pity.js` 第 57 行），实际每次点击消耗 6 个（顶级 7 个、神级 4 个）。序列错位导致末次抽取落到与首次相同的中级池（同为「石斧」）。修正注入序列（`D5` 6 元、`D5_TOP` 7 元、`D5_GOD` 4 元）后收敛断言通过（石斧→木碗），且残留随机数计数精确归零验证了消耗模型。
2. **次轮失败**（阶段 D 等待「星斗小村神级保底：1 / 50」超时）：「重新选择出身」不会清零当前出身计数（按出身隔离设计），星斗小村仍为上一阶段的 6/50。改用全新出身「武魂城世家」（0/50）执行神级验收，并追加断言「神级不得影响其他出身计数（星斗小村 6/50 不变）」，随即通过。

两轮失败均未产生任何产品代码改动；修复仅涉及烟测脚本。修复后 `npm run test:browser` EXIT=0，另直接运行 `node frontend/browser-smoke.mjs` 亦 EXIT=0（连续两轮全绿）。

## R2-1. R1 验收不足

R1 的产品实现方向成立，但浏览器证据不足，不能支持“全部验收点通过”：主场景只执行 5 次，并在 `page.evaluate` 内调用 `HTMLElement.click()`；只覆盖 1920、1440、390 三档视口；只比较操作条整体矩形，没有逐按钮、焦点、安全锁尾随点击和离开重进证据。本节保留 R1 历史原文，并以 R2 的严格场景取代其不完整结论。

## R2-2. 真实鼠标实现

`frontend/browser-smoke.mjs` 的 BUG-DIALOG-005 段已改为真实 Chrome 鼠标：先把“重新觉醒”滚动到可见区域，捕获一次 `boundingBox` 与中心坐标，随后只使用 `page.mouse.click(x, y)` 固定坐标点击。`page.evaluate` 仅用于读取 DOM、矩形、焦点、随机数残留和创建期草稿，不再调用 `HTMLElement.click()` 或 `dispatchEvent()`。

每次点击后均记录按钮是否存在、是否可见、是否禁用、当前焦点、按钮布局矩形、旧结果、保底、`aria-busy` 与随机序列残留。按钮的 hover transform 被单独扣除，矩形比较使用文档坐标，避免把合法悬停视觉位移误判为布局跳动。

页面全局 `html { scroll-behavior: smooth }` 会使 `scrollIntoView` 平滑滚动约百毫秒，连点期间视口仍在漂移（探针实测 390 视口 scrollY 141→166→184→194，而按钮文档坐标恒为 848.42）。因此瞄点显式使用 `behavior:'instant'` 取消平滑滚动，并把所有布局矩形转换为文档坐标（视口坐标 + scrollX/scrollY）：只比较内容真实位置，视口自身的滚动不参与判定。

## R2-3. 10 次固定坐标连续点击

- 星斗小村首次觉醒为石斧，保底 1/50；
- 同一固定坐标真实鼠标连续点击 10 次，相邻点击均小于 250ms；
- 10 次焦点均为“重新觉醒”，按钮始终存在、可见、未禁用；
- 每次点击的按钮 x/y/width/height 与第一次相比均不超过 1px；
- 处理中旧结果“石斧”保持并压暗，提示条可见，确认按钮禁用；
- 保底逐次从 1/50 增至 11/50，注入的 60 个随机值恰好耗尽；
- 停止点击后约 329ms 收敛为注入序列最后结果“木碗”，焦点仍在“重新觉醒”。

## R2-4. 自动停止与安全锁

- 顶级：真实鼠标抽到顶级后不停止，后续低级/中级抽取继续执行，保底累计至 14/50；
- 神级：34ms 内立即展示并只清当前出身，安全锁内继续对原坐标点击 3 次，结果、保底和随机数残留均不变化，约 670ms 后解锁；
- 49→50：13ms 内立即展示并解锁自选神级，安全锁内对重新瞄点后的“重新觉醒”固定坐标尾随点击 3 次（封顶后解锁行使操作条重排，锁内需重取一次坐标），不消耗随机数、不改变结果、不误开任何弹窗且无 51/50，约 662ms 后解锁；
- 已 50/50：安全锁结束后普通非神级可以继续快速重抽，保底保持 50/50，不重复触发首次封顶停止。

## R2-5. 离开与重新进入

快速重抽开始约 20ms 后真实点击“重新选择出身”，等待超过 250ms 后出身页没有被陈旧回调改写。重新选择原出身并进入觉醒页，再等待超过 650ms：页面恢复干净的“开始觉醒”状态，`aria-busy=false`，无旧结果、无提示、无安全锁；离开前已经完成的抽取保留在当前出身保底中（2/50），没有回滚。

## R2-6. 五档视口与逐按钮矩形

真实 Chrome 覆盖 1920×1080、1440×1000、1024×900、768×900、390×844。每档均分别验证：

- 三按钮形态：重新选择出身、重新觉醒、就是它了；
- 四按钮形态：增加自选神级武魂；
- 处理中与收敛后的操作条及每个同名按钮布局矩形差值均不超过 1px；
- 页面无横向滚动，提示条不越过视口，焦点保持在“重新觉醒”；
- 390px 先滚动到实际按钮区域再使用固定坐标点击，四个按钮仍可完整参与矩形断言。

## R2-9. 失败与修复记录（五次 test:browser 失败均为脚本自身问题，产品代码零改动）

1. **阶段 B 收敛后按钮视觉位移 1.74px**：`.btn { transition: all 0.25s }` 与 `:hover { transform: translateY(-2px) }` 使快速连点反复重置悬停抬起过渡，收敛后视觉 y 漂移 0 → -0.9 → -2px；实测 `.awaken-actions` 布局恒定（1920 下 y=914.94 不变），位移纯为悬停视觉效果。修复：逐按钮比较“视觉矩形减去 transform 位移”的布局矩形（≤1px），不再误判。
2. **阶段 D 其他出身文字格式**：「其他出身：星斗小村 14/50」一行不带空格，按“神级保底：14 / 50”风格书写断言而失败。修复：改用 `/其他出身：星斗小村 14\/50/`。
3. **阶段 E 安全锁时长误报 <600ms**：解锁时长从“3 次尾随点击之后”起算，计时起点晚于停止点击约 200ms。修复：从停止点击时刻起算（实测 670ms/662ms）。
4. **阶段 E 尾随点击误开“自选神级武魂”弹窗**：50/50 时 `.awaken-left` 新增解锁行使操作条下移并重排为四按钮，封顶前捕获的旧坐标恰好落在新出现的「✦ 自选神级武魂 ✦」上（探针 `elementFromPoint` 命中确认），三次尾随点击因此打开了神级自选 ModalDialog；其 `.modal-mask` 蒙层盖住按钮，使阶段 F 重瞄后的真实点击全部打到蒙层、焦点断言失败。修复：锁尾随点击前对“重新觉醒”重新瞄点，并追加“尾随点击后不得出现 `.modal-mask`”守卫断言。
5. **阶段 H 390 视口连点漂移**：`html { scroll-behavior: smooth }` 使瞄点 `scrollIntoView` 平滑滚动约百毫秒，连点期间视口仍在漂移，固定坐标点击落空。修复：瞄点显式 `behavior:'instant'`；布局矩形改用文档坐标（视口坐标 + scrollX/scrollY）。

五次失败全部只改 `frontend/browser-smoke.mjs`，未触碰任何产品源码（多轮 `vite build` 产物哈希一致）；修复后完整重跑通过。
